# 模块 B：动画系统

本模块覆盖的原技能：Remotion、Manim、tri-lottie、Konva.js、Blender、Three.js、Godot、Motion Canvas、Motion（JS 动画库）、Ola、Anime.js、Shifty、Two.js、TweenJS、LUME、gifenc、Babylon.js、Proton 粒子

本模块只解决一个问题：稿子定型之后，怎么给每页加上恰当的动画，并且让动画在真实播放时不出错。动画只服务讲解，讲到哪、出现哪；没讲到的东西不要提前出现，不要为了好看多加动画。

> 阅读约定：本模块讲的是做法，不是概念。每类动画都写适用场景与一个做法要点。凡是提到平台规则、价格、额度、版本兼容性而没有把握的，一律写“需核实”，不编数字。

---

## 第一节：PPTX timing 模型总览

一份 PPTX 里的动画，由时间线统一管理。时间线里装着四类动画、切换与触发器。理解这张总表，再动手排动画。

| 组成部分 | 是什么 | 在时间线里的位置 |
|---|---|---|
| 进入动画 | 元素怎么出现 | 时间线的开头 |
| 强调动画 | 元素出现后怎么被突出 | 时间线的中间 |
| 退出动画 | 元素怎么消失 | 时间线的结尾 |
| 动作路径 | 元素沿着哪条路线移动 | 可出现在任意一段 |
| 切换 | 一页怎么翻到下一页 | 两页之间 |
| 触发器 | 点一下哪个元素，才播放哪段动画 | 挂在指定的动画前面 |
| 时间线 | 上面所有内容的播放顺序、延迟与节奏 | 整页动画的总表 |

### 1.1 四类动画总表

| 类别 | 适用场景 | 一个做法要点 |
|---|---|---|
| 进入动画 | 标题、要点、图片、数据第一次出现时 | 一次只进一组，先讲的先出现，后讲的后出现，不要让整页同时出现 |
| 强调动画 | 要突出的数字、关键词、结论句 | 出现之后再强调，不要一边出现一边强调，两件事叠在一起看不清 |
| 退出动画 | 内容讲完要让位，给下一组内容腾地方 | 退出之前留半拍停顿，让听众看完再消失，消失得太急会打断思路 |
| 动作路径 | 箭头、流程、路线、位置变化 | 路线要短、要直，绕圈子的路线讲不清方向，讲完再检查终点位置对不对 |

### 1.2 切换

切换是页与页之间的过渡，不是页内的动画。

| 要点 | 内容 |
|---|---|
| 适用场景 | 章节切换、场景切换、从一页主题转到另一页主题时 |
| 做法要点 | 全 deck 只用一到两种切换，风格统一；每页切换都不一样，翻页时风格会跳变 |
| 节奏 | 切换时长要短，拖得太长会打断讲解节奏；时长在「切换」选项卡的计时组里直接改秒数，数字越小翻页越快（来源：微软支持《设置切换的计时和速度》） |
| 禁忌 | 不要用切换代替页内动画，切换管翻页，页内内容出现要靠进入动画 |

### 1.3 触发器

触发器是“点一下才播放”的开关。

| 要点 | 内容 |
|---|---|
| 适用场景 | 讲者要自己控制节奏的地方，例如点一张图才展开下一层、点一个按钮才出现答案 |
| 做法要点 | 一个触发器只挂一段动画，触发目标写清楚是哪个元素，不要一个开关挂一串 |
| 检查 | 触发器挂的元素不能删，删了触发器就失效；改版式后要重新检查触发器绑定的元素还在不在 |
| 禁忌 | 不需要讲者控制的地方不要用触发器，全部用触发器会让讲者每页多点好几次鼠标 |

### 1.4 时间线：先快后慢可调

时间线是整页动画的播放表，顺序、延迟、节奏都在这里定。

| 要点 | 内容 |
|---|---|
| 先快后慢 | 元素入场可以快一点，落位后放慢，让听众的视线跟得上；节奏不要全程一个速度，全程匀速显得呆板 |
| 可调 | 延迟与时长都要留出可调的余地，排练时发现节奏不对，要能只改时间线、不动元素 |
| 顺序 | 时间线的顺序就是讲解的顺序，讲到哪、播到哪，顺序错了等于讲解顺序错了 |
| 检查 | 排完时间线要完整播一遍，只看静态页看不出顺序问题 |

### 1.5 擦除（画线）：线条从一端延长到另一端

- **是什么：** 入场动画“擦除”，方向“自左侧”，元素从左端向右端逐渐显现，看起来像线条在延长。
- **用在哪：** 折线图画线（每条线从左端画到右端）、时间轴生长、路线图行进。做法详见模块 D 第六节 6.2。
- **不要用在哪：** 柱形图不用擦除，用从下往上生长；标题、要点、图片不要用擦除，擦除只留给“线”本身。
- **分组：** 图表用擦除时分组选“按系列”，多系列依次画，错峰 0.2–0.3 秒。

### 1.6 自动播放（默认）：翻页即播，不用点

- **默认是什么：** 每页动画默认自动连播。翻到一页，第一组动画随翻页自动开始，其余组按“上一动画之后”自动衔接，讲者不用点鼠标，听众不用等点击。
- **为什么默认自动：** 实测教训（2026-11-15，24 页讲义）：动画全设成点击触发，网页版播放器（腾讯文档网页、Google Slides 等）常不播点击触发的动画，放映时没点鼠标就等于没有动画，用户原话是“做出来的 ppt 不是动画”。全点击触发不是“可控”，是“播不出来”。
- **触发方式映射表（p:timing 注入时按这张表写 nodeType）：**

| 触发方式 | 什么时候用 | p:timing 里怎么写 |
|---|---|---|
| 随页自动开始 | 每页第一组动画，翻页即播 | nodeType="withPrevious"，延迟 0 |
| 上一动画之后 | 同页后续各组，自动衔接 | nodeType="afterEffect"，延迟＝上一组时长，组与组错峰 0.1–0.3 秒 |
| 单击开始 | 只有讲者要自己控节奏的地方（点一张图才展开下一层、点按钮才出答案） | nodeType="clickEffect"，只挂需要控制的那一段 |

- **做法：** 每页第一组写 withPrevious，其余组写 afterEffect、延迟按上一组时长往后推；点击触发只挂在讲者要控制的那一段上，不要挂在整页。注入后验收器重读 p:timing 统计 nodeType：全页 clickEffect = 错，回本节重排。
- **例外：** 现场演讲、讲者要逐句控节奏的页，可以把个别组改成点击触发，但要写进交付说明、告诉用户哪几页要点；整页、整 deck 全改点击触发，不许。
- **网页播放器提醒：** 入场动画在网页版播放器里常播不出来，交付说明里如实写“请在 PowerPoint 或 WPS 桌面放映里看动画”，不要让用户在网页里以为动画没做。

### 2.1 怎么用这张表

| 情况 | 查表方法 |
|---|---|
| 有一页要点页要做列表入场 | 找适用页型里带“要点”的行，优先看 Anime.js、Motion、TweenJS 的错峰做法 |
| 有一页数据页要做数字滚动 | 找 Ola 那一行，数字滚动要导出成视频或 GIF 素材，PPT 原生没有数字滚动动画 |
| 有一页封面要做氛围背景 | 找 Proton 粒子、gifenc、Blender 的行，导出成 GIF 或视频作背景循环播放 |
| 有一页公式页要做分步推导 | 找 Manim、Motion Canvas、Shifty 的行，分步演示用顺序播放 |
| 有一页图表页要做分层出现 | 找 Konva.js、Two.js 的行，分层入场或导出成视频素材 |

### 2.2 两条选型铁律

- **能用原生动画的，不用视频素材。** 进入、强调、退出、动作路径四类能覆盖的，就用原生动画做，文件小、改起来快、播放不依赖外部播放器。
- **原生做不了的，才用视频或 GIF 素材。** 数字滚动、3D 旋转、粒子背景、数学推导视频，原生做不了，才导出成素材插进来。素材插进来之后，要检查文件大小与播放流畅度。

## 第三节：错峰写法

### 3.1 错峰是什么

错峰是让多个元素不一起出现，而是按顺序、隔一小段间隔依次出现。列表页、卡片页最常用这一招。

### 3.2 怎么做

1. 把要错峰的元素按讲解顺序排好，先讲的排在前面。
2. 第一个元素正常入场，后面的元素每个都比前一个晚一小段间隔出现。
3. 间隔要均匀，不要第一个隔得长、第二个隔得短，节奏乱了听众跟不上。
4. 间隔要短，太长会让讲者等动画，太短等于没错峰。

### 3.3 怎么排顺序

| 排法 | 什么时候用 | 注意 |
|---|---|---|
| 从上到下 | 列表、要点页，视线自然从上往下走 | 不要从下到上，视线要折返 |
| 从中间向两边 | 对称卡片、并列要点 | 中间的元素先出现，两边的后出现 |
| 按讲解顺序 | 讲解顺序与页面位置不一致时 | 顺序以讲解为准，不以位置为准 |

### 3.4 怎么定延迟

- 先定第一个元素的出现时间，再按间隔往后推。
- 延迟只加在“上一动画之后”的衔接上，不要每个元素都设成点击触发，讲者要点很多次鼠标。
- 排练时完整播一遍，感觉拖沓就把间隔调小，感觉拥挤就把间隔调大。
- 延迟调完要再播一遍，只改数字不复检，等于没改。

## 第四节：时间线写法

### 4.1 时间线是什么

时间线是整页动画的播放表：哪个动画先播、哪个后播、每个播多久、中间隔多久，全写在这里。

### 4.2 怎么做

1. 先列出这页要讲的要点，按讲解顺序排成一列。
2. 每个要点对应一组动画，写在时间线的对应位置。
3. 动画之间用“上一动画之后”自动衔接，需要讲者控制的地方才用点击触发。
4. 时间线排完，先播一遍，再调节奏。

### 4.3 怎么排顺序

| 原则 | 内容 |
|---|---|
| 顺序等于讲解顺序 | 讲到哪、播到哪，顺序错了等于讲解顺序错了 |
| 一组只讲一件事 | 一组动画只对应一个要点，不要一组动画里塞两个要点 |
| 退出与进入要分开 | 上一组内容退出之后，下一组内容再进入，不要一边退一边进 |
| 切换单独排 | 页间切换不写在页内时间线里，切换是两页之间的事 |

### 4.4 怎么定延迟与节奏

- 入场快、落位慢：元素出现可以快一点，落位后放慢，让听众的视线跟得上。
- 重点处留停顿：讲到结论、关键数据时，动画播完留半拍再往下讲，不要立刻跳到下一组。
- 节奏先快后慢可调：延迟与时长都要留出可调的余地，排练时发现节奏不对，只改时间线、不动元素。
- 全页动画的总时长要与这页的讲解时长匹配，动画播完了讲者还没讲完，或者讲者讲完了动画还没播完，都是时间线没排好。

## 第五节：触发器写法

### 5.1 触发器是什么

触发器是“点一下哪个元素，才播放哪段动画”的开关。触发器让讲者自己控制节奏，而不是动画自己一路播完。

### 5.2 怎么做

1. 先定哪几段动画需要讲者控制，只给这些动画挂触发器。
2. 触发目标写清楚是哪个元素，触发元素要醒目，讲者一眼能找到。
3. 一个触发器只挂一段动画，不要一个开关挂一串。
4. 挂完触发器，完整播一遍，点一下触发元素，确认对应的动画播出来了。

### 5.3 怎么排顺序

| 原则 | 内容 |
|---|---|
| 触发顺序等于讲解顺序 | 先触发的先讲，后触发的后讲，不要跳着触发 |
| 触发元素按出现顺序排 | 触发元素在页面上的位置，按讲解顺序从上到下、从左到右排 |
| 自动衔接与触发要分开 | 不需要控制的动画用自动衔接，需要控制的才用触发器，两类不要混在同一组里 |

### 5.4 怎么定延迟

- 触发动画的延迟从点击那一刻算起，不要设太长的延迟，点完半天没反应，讲者会以为没点中。
- 触发动画播完之后，下一组自动衔接的动画可以留一小段间隔，让听众看完再往下走。
- 触发器挂的元素不能删，删了触发器就失效；改版式后要重新检查触发器绑定的元素还在不在。

### 5.5 触发器的禁忌

- 不需要讲者控制的地方不要用触发器，全部用触发器会让讲者每页多点好几次鼠标。
- 触发元素不要藏在角落里，讲者现场找不到触发元素，等于触发器不存在。
- 触发器不要挂在会退出的元素上，元素退出了，触发器也就点不到了。

## 第六节：诚实红线——python-pptx 本身不支持直接加动画

### 6.1 必须写明的一点

**python-pptx 本身不支持直接加动画。**

这句话要写进包里，不许含糊。用 python-pptx 生成 PPTX 时，调用它的常规接口加不了动画。动画要靠向幻灯片 XML 注入 p:timing 时间线来实现。

### 6.2 注入的大致步骤

| 步 | 做什么 |
|---|---|
| 第一步 | 用 python-pptx 生成不带动画的 PPTX，元素、位置、文字全部先定好 |
| 第二步 | 打开目标幻灯片的 XML，找到放时间线的位置 |
| 第三步 | 按 PPTX 的时间线结构，写一段 p:timing 时间线，描述动画的类别、顺序、延迟、时长与目标元素 |
| 第四步 | 把这段 p:timing 注入幻灯片 XML，保存成新的 PPTX |
| 第五步 | 用验收器重读落盘的 PPTX，确认 p:timing 真实存在、指向的元素真实存在 |

### 6.3 核对步骤：在 PowerPoint 与 WPS 里实际播放检查

注入只是写进去了，不等于播得出来。核对必须在真实软件里播放检查：

1. 在 PowerPoint 里打开注入后的 PPTX，从头到尾完整播放一遍。
2. 在 WPS 里打开同一份 PPTX，再完整播放一遍。
3. 逐页核对：每组动画是不是按顺序播、延迟对不对、有没有动画失效、有没有元素错位。
4. 发现问题不要只在 XML 里猜，回到注入步骤改，改完重新注入、重新播放检查。
5. 两个软件都播通过，才算核对通过。只在一个软件里播过，不算通过，另一个软件必须补播。

## 第七节：验收门

验收门是交付前的最后一道关。验收不过，不许说“好了”，不许交付。

### 7.1 验收门总表

| 门 | 要求 | 怎么查 |
|---|---|---|
| 每页内容页至少 1 组动画 | 每页内容页都要有动画，不能有空白页 | 验收器重读落盘 PPTX，逐页查 p:timing 时间线 |
| 动画默认自动连播 | 每页第一组动画随翻页自动开始，其余组自动衔接；全页点击触发不通过 | 验收器重读 p:timing，统计每页 nodeType：第一组 withPrevious、其余 afterEffect；全页 clickEffect 列出来返工 |
| 核对命令跑过且全过 | 交付前跑动画核对命令，输出 PASS；FAIL 的页列出来返工，修完重新跑 | 跑 check_anim.py 看输出（见主 SKILL.md“动画核对命令”一节） |
| 全 deck 至少 1 种切换 | 整份文稿至少有一种页间切换 | 验收器重读落盘 PPTX，查切换设置 |
| 时间线先快后慢可调 | 入场快、落位慢，延迟与时长能调 | 播放检查时看节奏，排练时调时间线确认能改 |
| 动画顺序与讲解一致 | 先讲的先出现，后讲的后出现 | 对照讲稿逐页播放核对 |
| 动画没改动锁定内容 | 标题、正文、数据一个字都没变 | 对照模块 A 锁定前的定版稿比对 |
| 触发器绑定的元素存在 | 触发器指向的元素还在，没有失效 | 播放检查时逐个点触发元素 |

### 7.2 验收做法

- 验收由独立验收器做，验收器自己打开磁盘上的 PPTX 重读，不是读生成器的日志。
- 验收必须完整播放一遍，从第一页播到最后一页，中间不许跳页。
- 验收表逐项打勾，有一项没过，整份文稿就是没通过。
- 修完必须复检，复检只检修过的页与受牵连的页，复检通过才算过关。

### 7.3 验收不过怎么办

| 情况 | 做法 |
|---|---|
| 某页没有动画 | 回模块 B 补动画，补完重新跑验收 |
| 全页点击触发 | 回模块 B 按 1.6 改触发方式：第一组 withPrevious、其余 afterEffect 自动衔接，只留讲者要控制的那一段用点击触发，改完重新跑验收 |
| 动画顺序错了 | 回模块 B 重排时间线，排完重新跑验收 |
| 动画改动了锁定文字 | 按模块 A 的返工规则回对应的步骤，改完重新锁定、重新加动画、重新跑验收 |
| 切换缺失 | 回模块 B 补切换，补完重新跑验收 |
| 触发器失效 | 回模块 B 重新绑定触发器，绑完重新跑验收 |

### 7.4 一句话红线

**验收不过，不许说“好了”。**

质检表上有一项没打勾，文稿就是没完成。不要用“差不多”“应该没问题”放行，要么修掉，要么明确告诉用户哪一项没过、卡在哪一步。
