# 模块 D：图形与公式

本模块覆盖的原技能：Manim、Two.js、tri-lottie、Three.js、Babylon.js、Konva.js、Ola、Proton 粒子、Motion Canvas、gifenc、Remotion、Blender；底座做法对照 ppt-master。

> 阅读约定：本模块讲做法，不讲概念。凡是提到平台规则、价格、额度、版本兼容性而没有把握的，一律写“需核实”，不编数字。凡是写到动画库的方法名，只保留名字，不抄参数、不抄代码。核心就一句话：动画库里做的东西，最后都要变成视频、动图或图片文件，再放进幻灯片里播放；幻灯片软件自带的动画只负责页面内元素的出现与强调，不负责播视频。

## 第一节：Manim 公式逐步推导——公式一步步出现的做法

Manim 最适合讲数学：一行公式写出来，下一步公式跟着变，图形随公式一起动。听众看到的不是一张写满公式的静态页，而是一步步推出来的过程。

### 1.1 公式一步步出现的做法

| 步骤 | 做什么 | 做到什么程度算过关 |
|---|---|---|
| 第一步：拆步骤 | 把一整段推导拆成一步一行的短式子 | 每一步只变一个地方，变两处以上就再拆 |
| 第二步：定出场顺序 | 按推导顺序排好每一行的出现次序 | 顺序就是讲课的顺序，先讲的先出现 |
| 第三步：做书写动画 | 每一行公式像手写一样逐字写出来 | 写字的速度跟得上讲解的速度，不抢讲、不拖讲 |
| 第四步：做变形动画 | 上一步的式子平滑变成下一步的式子 | 不变的部分留在原地，变的部分移动到位，听众看得出哪里变了 |
| 第五步：配图形联动 | 公式变到哪一步，旁边的图形就跟着变到哪一步 | 图形变化与公式变化同步，图与式子互相印证 |

### 1.2 导出 MP4 插进 PPT 的流程

| 步骤 | 做什么 | 注意事项 |
|---|---|---|
| 第一步：定画幅 | 先定视频的宽高比，与幻灯片页面比例一致 | 画幅与页面不一致，放进页面会出现黑边或被裁切 |
| 第二步：定总时长 | 先算好整段推导讲多久，再按时长排动画节奏 | 时长按讲解语速算，不按动画库默认时长算 |
| 第三步：渲染成片 | 把写好的动画渲染成视频文件 | 渲染命令：manim -qm 文件.py 场景名（-qm=720p30；另有 -ql 480p15、-qh 1080p60、-qk 4K60、-qp 1440p60；默认不透明输出 MP4，透明场景出 MOV；出 GIF 用 --format=gif，v0.22 已移除旧 -i 开关）。来源：Manim 官方文档 docs.manim.community（当前稳定版 v0.22.1） |
| 第四步：检查成片 | 从头到尾看一遍成片，核对公式与图形 | 公式有没有错字，图形有没有错位，节奏有没有抢讲 |
| 第五步：放进幻灯片 | 把视频文件插到公式页，铺满页面或放在预留区域 | 视频放在页面上层，不被文字遮住 |
| 第六步：定播放方式 | 讲到这一页时点一下开始播放，或设为自动播放 | 现场讲用手动开始，录播用自动播放；播放设置在 PowerPoint「播放」选项卡的「开始」列表里选：按点击顺序（默认）、自动、单击时。来源：微软官方支持文档《Insert and play a video file from your computer》 |

**适用页型：** 公式页、要点页、数据页。公式推导之外的讲解，例如概念串讲、流程说明，用 Motion Canvas 的做法更合适，见本模块第八节对照表。

**注意事项：**

- 公式内容本身要先请懂行的人核对一遍，动画做得再好看也盖不住公式写错。
- 一段视频只讲一个推导，两个推导拼进一段视频，听众跟不上。
- 视频用 MP4（H.264 视频＋AAC 音频），这是微软官方推荐格式；另支持 MOV、WebM；WMV、AVI 在新版 PowerPoint 已弃用，插入时会被转码。来源：微软官方支持文档《Video and audio file formats supported in PowerPoint》。文件体积按插入后实测。

## 第二节：Two.js 矢量图——矢量图解画法、导出 SVG 与视频

Two.js 适合画矢量图解：直线、圆形、箭头、文字、渐变拼成的示意图，线条干净，放大不模糊。同一套画法可以出三种素材：静态图、动图、视频。

### 2.1 矢量图解画法

| 步骤 | 做什么 | 做到什么程度算过关 |
|---|---|---|
| 第一步：定图解结构 | 先画一张草图，定好有哪些图形、箭头指哪、文字放哪 | 草图上每个元素都有位置，不边画边想 |
| 第二步：画静态底图 | 用直线、圆形、箭头、文字、渐变把底图画出来 | 底图单独看也成立，不依赖动画才看得懂 |
| 第三步：分组 | 把要一起动的元素分到同一组，把要分开动的元素分开 | 一组只负责一个动作，组与组之间不互相牵连 |
| 第四步：加逐帧运动 | 用逐帧回调让图形旋转、移动、放大、缩小 | 每个动作只改一个属性，两个属性同时变就拆成两步 |
| 第五步：定出场顺序 | 按讲解顺序排好各组图形的出现次序 | 顺序就是嘴上讲的顺序，先讲的先出现 |

### 2.2 导出与插进 PPT

| 素材形式 | 做法 | 什么时候用 |
|---|---|---|
| SVG 图片 | 把画好的矢量图导出成 SVG 文件，直接插进幻灯片 | 只要静态图，不要动画；放大不模糊，适合打印与投影 |
| 视频文件 | 把逐帧运动录制或渲染成视频文件，插进幻灯片播放 | 图解要一步步动起来，讲到哪动到哪 |
| 动图文件 | 把短循环运动做成动图文件，插进幻灯片循环播放 | 动作短、要反复播，例如旋转、呼吸、脉冲 |

**注意事项：**

- SVG：PowerPoint 2019 起支持插入与编辑 SVG，Microsoft 365 也支持（含带滤镜的 SVG）；更早版本没有该功能。来源：微软官方《What's new in PowerPoint 2019》与《Edit SVG images in Microsoft 365》。插入后仍先在放映模式下看一遍。
- 矢量图的线条粗细、文字大小要按投影距离调，电脑上看着清楚不等于最后一排看着清楚。
- Two.js 没有内置补间与时间轴动画系统，官方做法是逐帧回调 two.bind('update', …) 加 two.play()（或创建时 autostart: true）。分组用 two.makeGroup()，Group 有 add/remove/children/getById/getByClassName/getByType 等方法，没有 clear()（清空场景用 two.clear()）。类型取值 Two.Types = webgl/svg/canvas，默认 svg。来源：two.js.org/docs 与 Two.js 源码（v0.8.24）。

## 第三节：Lottie 轻量动画——规格单先行，再做轻量矢量动效

Lottie 做法的核心是“先定规格单，再动手做”。规格单是一张表，写清这个动效要传达什么情绪、多长、多快、怎么缓动、分几层。规格单不定就动手，做出来的动效一定返工。

### 3.1 规格单：先定情绪、时长、缓动

| 规格项 | 写什么 | 怎么定 |
|---|---|---|
| 情绪 | 这个动效要让听众感到什么 | 轻松、稳重、兴奋、好奇，四选一，不写两个 |
| 人格 | 动效的性格像什么 | 轻快、利落、柔和、俏皮，四选一，与情绪一致 |
| 属性 | 哪个元素动、动什么属性 | 只写要动的元素与属性，不动的元素不写 |
| 时长 | 整个动效多长、每一步多长 | 总时长先定，再分到每一步；一步超过两秒就拆 |
| 缓动 | 动起来的速度变化 | 开头慢结尾快、开头快结尾慢、匀速，三选一，全场统一 |
| 层次 | 元素分几层、哪层先动、哪层后动 | 层数不超过三层，先动背景层，再动主体层，最后动文字层 |

**规格单做法：** 按上面六项先填表，填完再动手。规格单一次只定一个动效，一个动效一张单，不把三个动效写进一张单里。完整版共八步（来源：tri-lottie 原技能文档），上表为简化版；另有第 6 步主角元素（每时刻一个 hero）、第 7 步三层运动（主层 100%＋次层 30–50% 延迟 50–100ms＋环境层 10–20%）、第 8 步 1/3 法则校验（位移不超容器 1/3；3 个以上元素同时活跃不超 1/3；错峰总预算小于 500ms）。

### 3.2 再做轻量矢量动效

| 步骤 | 做什么 | 做到什么程度算过关 |
|---|---|---|
| 第一步：按规格单做 | 照着规格单里的情绪、时长、缓动、层次做 | 做出来的动效与规格单逐项对得上 |
| 第二步：分轻重 | 简单动效直接用属性变化做，复杂矢量动效再用 Lottie 资产 | 能用属性变化解决的，不上复杂资产 |
| 第三步：过质量门 | 做完按三级检查：规格对不对、播起来顺不顺、放进页面后看不看得清 | 三级都通过才算做完，有一级不过就改 |
| 第四步：转格式 | 把做好的动效转成动图或视频文件 | 转完先看一遍，转完与原效果一致才算完 |

### 3.3 转 GIF 与视频插进 PPT

| 素材形式 | 做法 | 什么时候用 |
|---|---|---|
| 动图文件 | 转成动图插进幻灯片，循环播放 | 动效短、要反复播，例如封面装饰、结尾点缀 |
| 视频文件 | 转成视频插进幻灯片，点一下播放 | 动效长、只播一次，例如要点逐项展开 |

**适用页型：** 封面页、要点页、结束页。规格单共八步（情绪目标、人格原型、主属性、时长、缓动族、主角元素、三层运动、1/3 法则校验），六端为 Web、安卓、iOS、鸿蒙、React Native、Flutter。来源：tri-lottie 原技能文档。

## 第四节：Three.js 与 Babylon.js 的 3D 页——网页 3D 展示、相机环绕、录制成视频

3D 页的做法是：先在网页里搭一个能转、能缩放的 3D 展示，再把展示过程录制成视频，放进幻灯片里播放。幻灯片本身不跑 3D，只播录好的视频。

### 4.1 Three.js：网页 3D 产品展示

| 步骤 | 做什么 | 做到什么程度算过关 |
|---|---|---|
| 第一步：搭场景 | 搭一个 3D 场景，放进产品模型 | 场景里有模型、有地面、有背景，不空荡 |
| 第二步：布光影 | 加灯光与阴影，让模型有立体感 | 模型明暗分明，关键部位有光，阴影不遮住细节 |
| 第三步：定相机 | 定好相机的起始位置与环绕路线 | 环绕一圈能看清产品四个面，不丢视角 |
| 第四步：加动画 | 让模型旋转、缩放，或做骨骼与变形动画 | 动画只突出产品特点，不做与产品无关的炫技 |
| 第五步：录制成视频 | 把相机环绕与模型转动录制成视频文件 | 录完看一遍，画面不抖、不卡、不穿帮 |
| 第六步：放进幻灯片 | 把视频插到 3D 页，铺满页面或放在预留区域 | 视频放在页面上层，播放时不被文字遮住 |

### 4.2 Babylon.js：产品 3D 展示加相机环绕

| 步骤 | 做什么 | 做到什么程度算过关 |
|---|---|---|
| 第一步：建引擎与场景 | 用引擎、场景、相机、灯光搭出展示底子 | 场景能正常显示，相机能自由转动 |
| 第二步：建模型 | 用网格搭建方法做出产品模型，或加载现成模型文件 | 模型比例正确，关键部位齐全 |
| 第三步：定相机环绕 | 让相机绕产品转一圈，或让产品本身每帧转动 | 转一圈不停顿，速度均匀，不忽快忽慢 |
| 第四步：录制成视频 | 把环绕过程录制成视频文件 | 录完看一遍，画面不抖、不卡 |
| 第五步：放进幻灯片 | 把视频插到 3D 页播放 | 与 Three.js 同一套放映做法 |

**许可说明：** Babylon.js 是 Apache-2.0 许可的开源 3D 引擎，许可来源为该项目官方仓库的许可声明。本模块只作动画映射对照：即把它的“网页 3D 展示加相机环绕”这一能力，对照成“录制成视频插进幻灯片”的做法，不复制它的代码，不改写它的许可。接口均已核实：材质 StandardMaterial/PBRMaterial、贴图 Texture、动画 Animation/AnimationGroup、骨骼 Skeleton/Bone、粒子 ParticleSystem、图形界面 AdvancedDynamicTexture（独立 @babylonjs/gui 包）、场景拾取 scene.pick；物理引擎现行推荐 V2 仅支持 Havok，Cannon.js/Oimo.js/Ammo.js 属已列入 Legacy 的 V1，不要并列为同一代后端。来源：doc.babylonjs.com。模型文件用 Blender 内置导出 glTF 2.0（.glb），glTF 2.0 为官方事实标准格式；.babylon 为 Babylon 自有格式，未见官方称其为推荐格式。Blender 导出器版本对应关系：已查官方文档仓库 Blender 导出器页，其说法已过期（写 v6 对应 Blender 2.8 测试版），官方现行文档里没有可用的版本对照表，仍未核实。

### 4.3 3D 页检查点

| 检查点 | 做法 |
|---|---|
| 只播视频 | 幻灯片里只放录好的视频，不放网页链接，不现场跑 3D |
| 时长克制 | 一段 3D 视频不超过 30 秒，超过就拆成两段 |
| 有字幕或讲解 | 3D 画面转动时，旁边配一句说明文字或口头讲解，不让画面空转 |
| 备一张静态图 | 视频播不出来时，页面上还有一张静态产品图顶上 |

**适用页型：** 封面页、数据页、结束页。更重的 3D 模型旋转、相机环绕与产品拆解，可用 Blender 的做法，见本模块第八节对照表。

## 第五节：Konva 交互示意——多图层分层入场、触发器做法

Konva 适合做可交互的图解页：一张画布上分多层，每层一个意思，讲到哪层亮哪层。放进幻灯片里时，交互变成“点一下出下一层”。

### 5.1 多图层分层入场

| 步骤 | 做什么 | 做到什么程度算过关 |
|---|---|---|
| 第一步：分层 | 把画布内容按意思分成若干层 | 一层只讲一件事，层与层之间不重叠意思 |
| 第二步：定层序 | 按讲解顺序排好各层的出现次序 | 顺序就是嘴上讲的顺序，先讲的先出现 |
| 第三步：做入场 | 每一层入场时带一个简单过渡，例如淡入或浮入 | 入场只用一种过渡，全场统一，不每层换花样 |
| 第四步：加滤镜 | 需要突出某一层时，给该层加滤镜或缓存效果 | 滤镜只用在要突出的那一层，用多了等于没突出 |
| 第五步：检查分层 | 所有层都出现后，整张图看起来完整 | 图层之间不互相遮挡，文字不被图形压住 |

### 5.2 触发器做法

| 做法 | 说明 | 什么时候用 |
|---|---|---|
| 点击触发 | 点一下页面上的某个元素，下一层出现 | 现场讲，讲到哪点到哪，节奏自己掌控 |
| 顺序触发 | 按顺序点一下，层按顺序逐个出现 | 流程固定，不想跳步 |
| 视频化 | 把分层入场录制成视频，插进幻灯片自动播放 | 录播，不想现场点，或要发给别人自己看 |

**触发器映射说明：** 画布上的交互在幻灯片里没有完全对应的功能，本模块的映射是“点一下出下一层”，用幻灯片软件自带的触发器或“上一动画之后”顺序播放来实现。触发器设置路径：PowerPoint「动画」选项卡→「高级动画」→「动画窗格」，选中已加动画的对象，点「触发器」→「单击时」→选对象（另有“书签时”触发）。来源：微软官方支持文档《Trigger an animation effect》。

**适用页型：** 目录页、要点页、图表页。

## 第六节：图表 7 种——适用场景与动画做法

图表页的规矩：先选对图表类型，再做动画。类型选错，动画做得再好看也救不回来。动画只做一件事：让听众的眼睛跟着数据的顺序走。

| 序号 | 图表 | 适用场景 | 动画做法 |
|---|---|---|---|
| 1 | 柱形图 | 对比几个项目的大小，例如各部门销售额、各月产量 | 柱子从下往上逐根生长，数值标签最后出现 |
| 2 | 折线图 | 看一个指标随时间的变化，例如月度增长、季度趋势 | 折线从左端向右端延长画出（擦除，自左侧，按系列），关键拐点停顿一下再标数字，做法见 6.2 |
| 3 | 饼图 | 看一个整体由哪几部分组成，例如市场份额、费用构成 | 扇形逐块出现，最大的一块先出现，其余按大小依次出现 |
| 4 | 散点图 | 看两个指标之间有没有关系，例如投入与产出、价格与销量 | 点逐个出现，点出现后再画趋势线 |
| 5 | 雷达图 | 对比一个对象在多个维度上的强弱，例如产品五项评分、团队六项能力 | 轮廓线从中心向外逐维展开，各维度数值最后标出 |
| 6 | 瀑布图 | 看一个数值从起点到终点中间经历了哪些增减，例如利润从收入到净利润的变化 | 柱子按顺序逐根累加，正向柱与负向柱用不同颜色区分 |
| 7 | 甘特图 | 看一个项目里各项任务的时间安排，例如谁先做、谁后做、哪项并行 | 时间条按开始时间依次出现，当前进行中的任务高亮 |

**图表动画通用检查点：**

| 检查点 | 做法 |
|---|---|
| 先出图形，后出数字 | 图形动完再出数字标签，数字先出会抢图形的注意力 |
| 一次只讲一个变化 | 一页图表只讲一个结论，两个结论拆成两页 |
| 颜色不超过五种 | 图表颜色按模块 C 的三色法来，超过五种就改回三色 |
| 坐标轴先定好 | 坐标轴与单位先出现，图形再动，听众先知道刻度再看数据 |

### 6.2 折线图画线动画：线条从一端延长到另一端

- **效果：** 入场动画用“擦除”，方向选“自左侧”。线条从左端向右端延长画出，像笔在纸上画线一样，终点落在右端。不要用“出现”“淡入”做折线，那两种是整条线突然出来，没有画线的过程。
- **分组：** 图表动画分组选“按系列”。单系列一次画完；多系列每条线依次画，线与线之间错峰 0.2–0.3 秒，一条画完再画下一条，不要多条线同时起笔。
- **时长：** 按数据点数量定，每段约 0.15–0.25 秒，全线 1–2 秒；数据点多（20 个以上）分段画或放慢到 2–3 秒，全线不要超过 3 秒，拖太长听众会等。
- **顺序：** 坐标轴与单位先出现 → 线从左向右画 → 关键拐点停顿一下 → 数字标签最后出现。标签不要在画线途中出现，线画完再标数。
- **触发：** 按底座第 5 节动画基调与模块 B 的触发规则定；讲解型默认“上一动画之后”自动衔接，需要讲者控制的地方才用点击触发。
- **注入做法：** p:timing 里用 animEffect 过渡 wipe(from left) 写擦除；图表分组写 bldLst/bldChart（bld="series"）。擦除的 presetID 以实机导出核对为准（需核实），不要凭记忆写数字。
- **检查：** 实机放映看三点：线是不是从左向右连续延长、有没有跳变；有没有整条线突然出现（有就是擦除没挂上）；多系列是不是一条画完再画下一条。有一项不过就回本节重排，不要带着错动画往下走。
- **备选：** 面积图、时间轴、路线图也用擦除自左；柱形图不用擦除，用从下往上生长。

### 6.1 数字滚动：Ola 归到数据图表一节

数据页的大数字与 KPI 页的指标数字，适合做“数字滚动”：数字从旧值平滑滚动到新值，中途改目标仍平滑过渡。这是 Ola 这一招在幻灯片里的对应位置。

| 项目 | 做法 |
|---|---|
| 放在哪 | 数字滚动归到本节数据图表一节，与大数字页、KPI 页一起做 |
| 怎么做 | 先在动画库里把数字滚动做成视频或动图文件，再放进幻灯片里播放 |
| 为什么不能直接做 | 幻灯片软件本身没有数字滚动动画，数字滚动效果必须先导出成视频或动图素材 |
| 注意事项 | 数字滚动的速度要跟讲解语速一致，滚得太快听众看不清终值，滚得太慢听众等得不耐烦；Ola 取值字段无固定清单，字段名由创建时传入的 key 决定（value/angle/x/y 只是示例），派生属性 _<key>（含 to、from）与 $<key>（目标值）；set() 的第二个参数会改实例的默认过渡时间、影响后续所有过渡，不是只影响本次（来源：Ola README 原文 'update it for any subsequent transition'，源码覆写 this.time）。支持的运行环境版本范围：已查 Ola README、package.json、npm 页三处，均无版本范围说明，仍未核实，写代码前按现代浏览器实测。 |

## 第七节：粒子点缀——Proton 粒子做封面与结尾背景

粒子背景是封面页与结束页的氛围担当：星空、飘雪、烟花这类轻粒子效果铺在背景上，页面立刻有了动感。粒子只做背景，不抢前景的标题与文字。

### 7.1 三种粒子背景

| 背景 | 做法 | 什么时候用 |
|---|---|---|
| 星空 | 细小亮点缓慢闪烁、缓慢漂移 | 深色封面、科技主题、夜晚氛围 |
| 飘雪 | 白色小点从上往下缓慢飘落 | 冬季主题、节日场合、轻柔氛围 |
| 烟花 | 亮点从一点炸开、向外扩散、渐渐熄灭 | 结束页、庆祝场合、收尾高潮 |

**粒子做法：** 用发射器加初始化加行为加渲染器搭出粒子效果。发射器定粒子从哪来，初始化定粒子的大小、颜色、速度，行为定粒子怎么动、怎么消失，渲染器定粒子画在哪一层。十几行配置就能出效果，配置项以官方文档为准。

### 7.2 导出 GIF 与视频循环播放

| 步骤 | 做什么 | 注意事项 |
|---|---|---|
| 第一步：做粒子动画 | 按上表搭出星空、飘雪或烟花的粒子效果 | 粒子数量适中，太多显乱，太少显空 |
| 第二步：导出素材 | 把粒子动画导出成动图或视频文件 | 动图适合短循环，视频适合长循环；Proton 官方没有导出功能（已查 README 全文与示例目录，无 export/worker/server 相关写法），导出走画布录制等库外方案；动图编码用 gifenc：GIFEncoder＋writeFrame，repeat -1 只播一次、0 无限循环、正整数为次数。来源：gifenc README。 |
| 第三步：放进幻灯片 | 把素材铺满封面页或结束页当背景，循环播放 | 素材放在最底层，标题与文字放在上层，不被粒子遮住 |
| 第四步：调透明度 | 粒子太亮就调淡，粒子太密就调稀 | 背景粒子以“看得出在动、看不清在动什么”为宜 |

**注意事项：**

- 粒子背景只用在封面、结尾、目录三页，正文页不用，粒子会干扰阅读。
- 驱动循环已核实：requestAnimationFrame(tick) 里每帧调 proton.update()，Proton 不自带循环；渲染不用手动调，update() 内派发事件由渲染器监听。来源：Proton 官方示例 pointzone.html 与 Proton.js 源码（proton-engine 7.1.5）。
- 多线程导出与服务端导出：Proton 官方无此写法（已查 README 与示例目录）。多线程分帧用 gifenc 的 Worker 做法：README 有 Web Workers 一节与 test/encode_web_workers.html 示例，但无内置 worker API，需自己搭 worker 架构；Node.js 写法见 test/encode_node.js。来源：gifenc README。
- 粒子素材的体积按插入后实测；循环次数由 GIF 文件自身的 repeat 设置决定（gifenc：-1 只播一次、0 无限循环、正整数为次数，来源：gifenc README）；PowerPoint 放映时可播放动画 GIF（来源：微软官方支持文档《Add an animated GIF to a slide》）。
