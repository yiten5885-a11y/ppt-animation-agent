# 模块 E 导出与交付

> 本模块只管一件事：把已经定稿、已经加好动画的稿子，变成能交出去、能当场放出来的成品。稿子没定型、动画没做完，不要进本模块。进本模块之前，先确认模块 A 的稿子已定、模块 B 的动画方案已定、模块 C、D 的页面与图形已做完。

## 本模块什么时候用

- 用户说“导出来”“交片”“发我”“能放了吗”“检查一遍”时，进本模块。
- 用户要把讲稿变成 HTML 演示稿、把讲解过程变成短视频、把动效变成 GIF 时，进本模块。
- 任何一次交付之前，都要走完本模块第五节的质检清单，清单不过，不许说“好了”。

## E1 把动画写进 .pptx 文件

### 先说清一个关键事实

python-pptx 这个库本身没有加动画的接口。不要假装它自带动画功能，也不要在任何地方写“用 python-pptx 加动画”这种话。正确的做法分两步：先用 python-pptx 搭出静态页面，再往幻灯片的 XML 里注入时间线。

### 步骤

1. **搭静态页。** 用 python-pptx 按模块 C 的版式把每一页的文字、图片、形状、位置都摆好，保存成 .pptx 文件。这一步只管静态内容，不管动画。
2. **定时间线。** 按模块 B 的动画方案，给每一页列一张动画清单：哪个元素先出现、哪个后出现、每个动画多长、元素之间错开多久、哪些动画要点一下才出现、哪些动画自动接在上一个后面。
3. **注入时间线。** 打开幻灯片对应的 XML，在其中写入 p:timing 时间线，把动画清单里的每一组动画写进去。进入动画、强调动画、退出动画、切换效果，都要落到时间线里，不要只写在文档里。
4. **保存并另存一份备份。** 注入完成后保存文件，同时留一份注入前的静态版备份。万一注入后文件打不开，还能从备份重新来。
5. **实机播放检查。** 把文件拿到 PowerPoint 或 WPS 里，打开放映模式，从头到尾实际播放一遍。只在代码里看 XML 不算检查通过，必须亲眼看到动画按清单动起来。
6. **修一处，重新播一遍。** 播放中发现任何一处动画不对，只修那一处，修完从那一页重新播放验证，不要只改不验。

### 注意事项

- 动画注入只改时间线，不要动静态页面的文字与版式。页面内容有问题，回到模块 A、模块 C 去改，不要在注入这一步顺手改内容。
- 不同版本的 PowerPoint、WPS 对时间线的支持有差别，同一份文件在两边都播一遍再交。某个动画在某一边播不出来，写进交付说明里，不要瞒着用户。
- 文件体积突然变大、打不开、提示修复，先看备份能不能正常打开，再定位是哪一步注入写坏了。修不好就回到注入前的静态版重做，不要在坏文件上反复补。
- 动画的播放软件版本、是否需要联网字体、视频素材是否内嵌，都要在交付说明里写清（见 E5）。

## E2 讲稿一键生成 HTML 演示稿

### 流程

1. **确认讲稿已定稿。** 讲稿还在改，HTML 演示稿不要生成。先走模块 A 把讲稿定型。
2. **按页拆讲稿。** 把讲稿按幻灯片页数拆开，每一页对应一段讲稿，写清这一页的标题、要点、配图、动画提示。
3. **生成 HTML 演示稿。** 用拆好的逐页内容生成一份 HTML 演示稿，每页一个屏幕，支持键盘或点击翻页。演示稿里要保留模块 B 定好的动画节奏：要点逐个出现，而不是整页一次性全露出来。
4. **检查翻页与动画。** 在浏览器里从头到尾翻一遍，确认每一页的要点出现顺序对、翻页不断、图片能加载、文字不溢出。
5. **打包交付。** 把 HTML 文件与用到的图片、字体、视频素材放在同一个文件夹里一起交付，不要只发一个单独的 HTML 文件让用户自己找素材。

### 演示稿结构清单

- 每一页都有标题、要点、翻页提示，缺一项不算做完。
- 演示稿首页写清主题、演讲人、日期，不要直接从第二页开始。
- 动画提示要写在页面里，不要只写在备注里：观众看不到备注，讲的人翻页时要能一眼看到下一步出什么。
- 演示稿里用到的每一张图片、每一段视频，都要和 .pptx 版用同一份素材，不要两边各用一套。
- 演示稿做完后，在常用的两种浏览器里各打开一遍，确认翻页、动画、图片都正常。

### 注意事项

- HTML 演示稿是演示用的另一份成品，不是 .pptx 的替代品。用户要的是 .pptx，就交 .pptx；用户要的是网页演示，才交 HTML。
- 演示稿里不要内嵌没有来源的素材。图片、字体、视频的来源与许可，写进交付说明。
- 在用户自己的电脑上打开验证一遍再交。只在自己的机器上能打开，不算交付通过。
- 演示稿的翻页方式、是否自动播放、每页停留多久，事先和用户定好，不要自己默认。

## E3 Remotion 视频导出：把讲解过程做成短视频再插回 PPT

### 什么时候用这一招

- 某一页的讲解过程本身就是一段“逐句出现、逐项展开”的表演，靠 PPT 自身动画讲不清时，用这一招。
- 数据页的数字变化、图表生长、要点逐个展开，需要精确到帧的节奏时，用这一招。
- 适用页型：要点页、数据页、结尾页。

### 流程

1. **先写分镜。** 这一段视频讲什么、每句话对应哪个画面、每个要点什么时候出现、总时长多少，先写成一张分镜清单，再动手做视频。
2. **做视频。** 按 Remotion 的做法，用代码写出带时间线、字幕、图表动效的短视频，节奏由时间线精确控制。字幕要和讲解词逐句对上，不要出现字幕比声音快或慢。
3. **导出成 MP4。** 把做好的视频导出成 MP4 文件，确认分辨率、帧率、时长符合交付要求。
4. **插回 PPT。** 把 MP4 作为视频素材插入对应的幻灯片页面，摆好位置与大小，设好播放方式（点击播放还是自动播放）。
5. **实机播放检查。** 在 PowerPoint 或 WPS 里实际放映，确认视频能正常播放、声音（如果有）正常、字幕清晰、播完能顺利翻到下一页。

### 导出前检查表

- [ ] 分镜清单里的每一句讲解词都有对应的画面，没有哪句话没画面。
- [ ] 字幕逐句校对过，没有错字、漏字，字幕出现的时间和讲解词对得上。
- [ ] 图表动效的数字和讲稿里的数字一致，改过数字的地方重新导出过。
- [ ] 视频总时长和这一页计划讲的时间对得上，太长就剪短，不要让观众等视频播完。

### 注意事项

- 视频是素材，不是整份 PPT。不要把整份 PPT 做成一个视频交出去，除非用户明确只要视频。
- 视频文件会让 .pptx 体积变大。交付前确认文件大小用户能接收，太大就先和用户商量压缩或分开交付。
- 视频素材要内嵌进 .pptx，不要只放链接。只放链接的视频，换一台电脑就播不出来。
- 字幕文字要校对一遍，错字、漏字在导出前改掉，不要等交片后才发现。

## E4 GIF 导出：gifenc 把 Canvas 动画编成循环 GIF 插进 PPT

### 什么时候用这一招

- 动效本身很轻、需要一直循环播放时，用 GIF，不用视频。
- 封面、结尾、目录页想加一点氛围感（飘动的星空、雪花、烟花粒子背景）时，用 GIF 作背景循环播放。
- 适用页型：封面页、要点页、结尾页。

### 流程

1. **先定循环内容。** 这个 GIF 要表现什么、循环一次多长、放在页面的哪个位置、会不会抢正文的注意力，先定好再做。
2. **做 Canvas 动画。** 在画布上把动效做出来，确认动画本身流畅、元素不闪烁。
3. **逐帧编码。** 用 gifenc 把 Canvas 动画一帧一帧编码成 GIF，设好每帧的停留时间、循环次数、是否透明。循环次数一般设成无限循环，让它在页面上一直动。
4. **检查体积与清晰度。** 导出的 GIF 太大就减帧、减尺寸、减颜色；太糊就调回清晰度。体积与清晰度的取舍，事先和用户商量。
5. **插进 PPT。** 把 GIF 作为图片素材插入对应的幻灯片页面，摆好位置与大小。背景类 GIF 放在最底层，不要盖住文字。
6. **实机播放检查。** 在 PowerPoint 或 WPS 里实际放映，确认 GIF 能循环播放、不会卡在第一帧不动、不会盖住正文。

### 注意事项

- GIF 没有声音，适合纯视觉动效。需要声音的讲解过程，走 E3 的视频路线，不要用 GIF 硬凑。
- GIF 循环播放时不要让它抢走观众的注意力。背景动效要克制，正文区域不要放循环 GIF。
- 同一份 PPT 里 GIF 不要放太多，放多了文件会变大、播放会变卡。每放一个，都要在质检清单里记一笔。
- gifenc 的多线程用法已核实：README 有 Web Workers 一节与 test/encode_web_workers.html 示例，但无内置 worker API，需自己搭 worker 架构；Node.js 写法见 test/encode_node.js。来源：gifenc README。

## E5 逐项质检清单：验收不过不许说“好了”

质检分四组，全部打勾才能交付。任何一组有一项不过，就回到对应的模块去修，修完重新走一遍质检。不要跳过质检，不要凭感觉说“应该没问题”。

### 内容质检

- [ ] 每一页的标题、要点、数字、日期、人名都和定稿的讲稿一致，没有错字、漏字、多字。
- [ ] 每一页的数字都和来源材料对得上，改过数字的地方有据可查。
- [ ] 引用、数据来源、图片来源都已写清，没有来源不明的内容。
- [ ] 讲稿里的每一页都有对应的幻灯片，没有漏页，也没有多余的页。
- [ ] 封面、目录、结尾页的信息完整，没有占位文字、没有“待补充”。

### 版式质检

- [ ] 每一页的标题、要点、图片都在页面安全区内，没有文字溢出页面、没有图片被裁掉一半。
- [ ] 全 deck 的字体、字号、颜色、间距保持一致，没有某一页突然换一套样式。
- [ ] 图片清晰，没有拉伸变形，没有模糊、没有水印遮住正文。
- [ ] 品牌元素（标志、主色、字体）按底座第 4 节的要求放对了位置，没有放错、没有漏放。
- [ ] 在目标放映尺寸下检查过一遍，换一台电脑、换一个投影比例也不会乱版。

### 动画必检（单列，逐项核对）

- [ ] 每页内容页至少 1 组动画：每一页有正文内容的页面，至少有一组进入动画或强调动画，没有动画的空白页不算过关。
- [ ] 动画默认自动连播：翻到一页不用点就自己播，第一组随翻页自动开始，其余组自动衔接；全页点击触发不通过，验收器重读 p:timing 统计 nodeType。
- [ ] 全 deck 至少 1 种切换：整份 PPT 至少有一种页面切换效果，切换方式全 deck 统一，不用每页换一种。
- [ ] 时间线先快后慢可调：动画的节奏是先快后慢，时间线上的时长、延迟都能调，改一个数字就能改节奏，不用重做整页。
- [ ] 触发器点一点才出现：凡是设计成“点一下才出现”的内容，实际放映时点一下才出现，不点不出现，点第二下才出下一个。
- [ ] 视频/GIF 素材能正常播放：每一处视频、GIF 素材在 PowerPoint 或 WPS 的放映模式下都能正常播放，没有黑屏、没有卡在第一帧、没有播完翻不过页。
- [ ] 动画顺序和讲稿一致：动画出现的顺序就是讲稿讲解的顺序，没有先出结论再出论据、没有要点乱序。
- [ ] 动画不抢正文：动效克制，没有满屏乱飞、没有闪烁、没有让观众看不清正文的动画。
- [ ] 错峰与延迟都已验证：列表逐个出现、卡片依次入场的错峰，在实际放映里逐个出现，没有两个元素同时撞出来。

### 视觉必检（单列，逐项核对）

- [ ] 每页内容页至少 1 个视觉元素：每一页有正文内容的页面，至少有 1 个图片、原生图表、形状示意图组、视频或 GIF，纯文字页为零。
- [ ] 封面有图：封面至少有 1 个视觉元素，留白不超过一半；章节页有本章主图；结尾页有收束图。
- [ ] 结构示意图画对了：链表、栈、队列、树、图、流程图按模块 F 第三节图谱画，节点、箭头、标注都对得上讲稿，没有画错结构。
- [ ] 图注齐全：每张图下方有一行图注，写清这张图在讲什么；没有图注的图不算过关。
- [ ] 数据图是原生图表：数据图用 PPT 原生图表做，不是一张截图；一张图系列数不超过 4 条，颜色不超过五种。
- [ ] 图片许可与尺寸：每张图的来源与许可都确认过，写进交付说明；图片压过合适尺寸，没有几 MB 的原图塞进包里。
- [ ] 渲染看过一遍：形状对齐、字没溢出、线没交叉、图没变形、图没被裁掉一半。
- [ ] 对比度：标题、副标题、页脚、行标签的字色与底色对得上，深底浅字、浅底深字；验收器重读文件逐项核对字色与所在底色（背景或卡片填充），深色字压深底、浅色字压浅底的页列出来修。
- [ ] 空白占位清零：无字占位形状（空白芯片、空白卡片、空白条、空白文本框）一律删掉，不许留着；占位文字、“待补充”清零。
- [ ] 装饰不盖字：装饰圆、色块、线条、粒子背景不许盖住文字，渲染核对每页，字被盖住的页列出来修。
- [ ] 竖条收进卡片：卡片左侧装饰竖条收进卡片内，上下左右各留空，不顶圆角边、不伸出卡片外。

### 交付说明怎么写

每一次交付，都附一份交付说明，写清下面几项，缺一项不算交完：

1. 本次交付了什么：文件名、页数、版本号、修改了什么。
2. 动画清单：每页用了哪些动画、哪些是触发器、哪些是自动播放。
3. 播放要求：用 PowerPoint 还是 WPS、哪个版本以上、是否需要联网、字体是否内嵌。
4. 素材清单：视频、GIF、图片素材的来源、大小、是否内嵌。
5. 插图清单：每页配了什么图（示意图、数据图、照片还是 AI 图）、图怎么来的（程序画、图库、AI 生图）、来源与许可。
6. 已知问题：播放中发现但还没修的问题、某个动画在某个软件里播不出来的情况，如实写清。
7. 下一步：用户看完之后要确认什么、要回什么意见。

### 交付后

- 用户反馈“这里要改”，只改反馈的那一处，改完按 E5 重新质检那一页，不要顺手改别处。
- 用户确认“可以了”，把最终版文件与交付说明一起归档，版本号升一位，底座第 9 节记一笔：这次交付改了什么、学到了什么。
- 交付后发现播放问题，先问用户是在哪个软件、哪个版本上播的，再定位，不要猜。

## E6 交付文件命名与版本管理

- 文件名写清主题、版本、日期，示例格式：主题-v1.0.0-20261115.pptx。不要只写“最终版”“最新版”这种分不清先后的名字。
- 每改一版，版本号升一位，旧版留档不删除。用户问“上一版呢”，要能马上找出来。
- 静态备份、注入后成品、HTML 演示稿、视频与 GIF 原素材，分文件夹存放，不要全堆在一个文件夹里。
- 每次交付都在底座第 9 节记一笔：这一版改了什么、为什么改、质检结果如何。

## E7 常见导出故障排查

### 文件打不开

- 先打开注入前的静态备份，确认备份本身能打开。备份能打开，问题出在注入这一步，回到 E1 第三步重做。
- 备份也打不开，问题出在静态页搭建这一步，检查最近一次改动加了什么形状、图片、字体，逐个去掉再试。

### 动画不动

- 先确认时间线确实写进了对应幻灯片的 XML，不要只改了第一页就以为全 deck 都有。
- 再确认动画的触发条件：设成点击触发的，实际放映时要点一下；设成自动接续的，检查前一个动画是否正常播完。
- 全页点击触发时先查生成默认值：是不是触发方式写错了，按模块 B 1.6 改成第一组 withPrevious、其余 afterEffect 自动衔接，不要只在播放器里反复点。
- 换一个软件试：PowerPoint 里不动，换 WPS 试一次；反过来也一样。两个都不动，再回头查时间线。

### 视频播不出来

- 先确认视频已经内嵌进文件，而不是只放了一个外部链接。只放链接的视频，换电脑、换文件夹就播不出来。
- 再确认视频格式与编码是播放软件支持的，不支持就重新导出一份再插。
- 视频太大播起来卡，先和用户商量是压缩视频还是拆开交付，不要直接交一个卡顿的版本。

### GIF 不动或只显示第一帧

- 先确认 GIF 本身能在浏览器里循环播放。浏览器里也不动，问题出在导出这一步，回到 E4 重新编码。
- 浏览器里能动、PPT 里不动，检查 GIF 是不是被当成静态图片插入的，重新按图片素材插入一次。
- GIF 太大导致翻页卡顿，减帧、减尺寸后再插，不要硬塞。

### 换电脑就乱版

- 先确认字体是否内嵌、是否随文件一起交付。字体缺失是最常见的乱版原因。
- 再确认图片、视频素材是否内嵌，外部素材换电脑就丢。
- 最后确认放映比例与目标电脑一致，比例不对先调比例再调版式。

### 修好之后

- 每修好一个故障，都按 E5 重新质检受影响的那几页，质检通过才算修好。
- 故障原因与修法记进底座第 9 节，下次遇到同样的故障直接翻记录，不要从头再查一遍。

## 本模块的“需核实”清单（2026-11-15 核对后）

- Morph 切换已核实：创建与播放需 Microsoft 365（1511 版或更新）、PowerPoint 2019/2021 或网页版；PowerPoint 2016（Click-to-Run 1511 版或更新）只能播放、不能创建，否则播 Fade。来源：微软官方支持文档《Use the Morph transition in PowerPoint》。
- python-pptx 与 p:timing：OOXML 动画时间线元素确为 p:timing（来源：Microsoft OpenXML 文档，ISO/IEC 29500-1）；python-pptx 官方文档的功能清单与 API 目录里没有 animation/timing 条目（来源：python-pptx.readthedocs.io 首页），但未找到“没有动画接口”的正面表述，属缺席证据；注入 p:timing 后在不同版本 PowerPoint、WPS 里的兼容情况仍以实机播放结果为准，仍未逐项核实。
- Remotion、gifenc 导出命令已核实：Remotion 用 npx remotion render <入口> <合成ID> <输出路径>（或 Studio 点 Render 按钮），--codec 默认 H.264，--quality 在 v4.0.0 起改名 --jpeg-quality（0–100），来源：remotion.dev/docs/cli/render；gifenc 的 quantize、applyPalette、GIFEncoder、writeFrame、finish 均存在，Worker 与 Node 示例见 README，来源：gifenc README。
- 本模块没有提到的导出格式、播放软件、版本要求，一律写“需核实”，不编数字、不编地址。
