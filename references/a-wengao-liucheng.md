# 模块 A：稳稿底座——以 wengao-ppt 为准

本模块覆盖的原技能：稳稿 PPT（wengao-ppt）

本模块只解决一个问题：让一份演示文稿在动手加动画之前，先把稿子彻底定下来，并且定下来的东西有办法证明。稿子没定型，动画做得越早，返工的代价越大；没有独立检查的定稿，等于没定稿。

> 阅读约定：本模块讲的是做法，不是概念。每一步都写清进来什么、出去什么、怎样算通过、哪里最容易返工。凡是提到平台规则、价格、额度、版本兼容性而没有把握的，一律写“需核实”，不编数字。凡是标“开发候选”或“未验证”的能力，只写方法与契约，不写成已验证。

---

## 第一节：底座是什么

### 1.1 一句话定位

稳稿 PPT（WenGao PPT）是一套本地优先、讲确定性契约的 PPTX 生成与美化引擎：原始材料进来，或者已有的 PPTX 进来，出去的是一份结构、事实、版式都经过检查的 PPTX。

- 版本：v0.1.0-dev-candidate，开发候选，未公开发布到 SkillHub。
- 许可：MIT。
- 来源：用户自己的仓库，地址是 https://github.com/yiten5885-a11y/wengao-ppt ，无侵权问题，包内附 MIT LICENSE 全文与来源说明。

### 1.2 底座管什么、不管什么

| 底座管 | 底座不管 |
|---|---|
| 原始材料转成结构清晰的 PPTX | 动画的创意设计（那是模块 B 的事） |
| 已有 PPTX 的美化与版式统一 | 讲稿本身写得好不好（观点、逻辑由人负责） |
| 事实、文字、数据有没有丢、有没有错 | 现场演讲的发挥 |
| 版式、配图来源合不合规 | 没有材料凭空编一页内容 |
| 交付物能不能通过硬性质量门禁 | 门禁没通过还硬说“好了” |

### 1.3 最核心的方法：独立验收器

这是整个底座最关键的一条，必须融进每一次交付：

**所有评估结论，必须由独立验收器对磁盘上已经落盘的产物做物理重读来验证，绝不采信生成器自己报的结论。**

什么意思，分三句讲清：

1. 生成器说“我做完了、没问题”，不算数。验收器要自己打开磁盘上的 PPTX、PDF、渲染出来的像素、字形轮廓，一个一个重新读一遍。
2. 验收器与生成器互相独立。生成器不能给自己打分，也不能改验收结果。
3. 没通过硬性质量门禁的产物，绝不静默放行。要么修好重验，要么明确告诉用户哪一项没过、卡在哪一步。

这条方法不只用在稿子阶段，也用在动画阶段（见第七节）。动画加完，同样要由验收器重读落盘文件才算数。

## 第二节：铁律——先稳稿、后动画

### 2.1 一句话铁律

**稿子不定型，不许动动画。**

这里的“稿子”包括四样东西：结构、事实、文字定稿、版式定稿。四样缺一样，都算没定型。

### 2.2 为什么必须先稳稿

| 原因 | 讲清 |
|---|---|
| 动画绑在元素上 | 一个动画挂在一个标题、一段文字、一张图上。文字一改、元素一删、位置一挪，挂在上面的动画就跟着错位、失效，或者指向一个不存在的元素 |
| 改稿的代价会放大 | 没动画时改一句话只要改一句话。有动画时改一句话，可能要重排时间线、重调错峰、重设触发器，一处改动牵出一串改动 |
| 讲稿顺序决定动画顺序 | 动画的播放顺序就是讲解的顺序。讲解顺序没定，动画顺序就没法排，排了也是白排 |
| 质检没法做 | 动画质检要对照定稿逐页播放检查。稿子还在变，质检结果第二天就作废，等于没检 |

### 2.3 什么叫“定型”

定型不是“大概写完了”，而是同时满足下面四条，并且由验收器重读验证过：

1. 讲稿全文写完，逐字稿与提纲一一对应，没有“这段以后再补”的空位。
2. 每页的标题、正文、数据、图片位置都已确定，文字不再增删改。
3. 每页的版式已确定，包括分区、留白、字号层级、配色，整份文稿风格统一。
4. 讲者本人已经通读一遍，确认顺序合理、没有逻辑跳跃、没有前后矛盾。

四条缺一条，就回到对应的步骤去补，不许带着缺口往下走。

## 第三节：标准流程——五步 CLI

底座的标准流程是五步，按顺序串行走，不许并行、不许跳步、不许把两步打包成一步做。任何一步没通过，就停在那一步，不许带着问题往下走。

| 步 | 命令 | 做什么 | 出什么 | 不许做什么 |
|---|---|---|---|---|
| 第一步 | precheck | 检查环境与材料齐不齐 | 检查结论：缺什么、能不能往下走 | 不许跳过检查直接跑生成 |
| 第二步 | run | 生成或美化 PPTX | 落盘的 PPTX 初稿 | 不许在这一步改验收标准 |
| 第三步 | validate | 独立验收器重读落盘产物 | 验收结论：通过，或哪一项没过 | 不许采信生成器自报的结果 |
| 第四步 | publish | 验收通过的产物定版 | 定版的交付稿 | 不许把没通过验收的产物定版 |
| 第五步 | export | 导出交付形态 | 按需导出的成品文件 | 不许在导出时偷偷改内容 |

### 3.1 第一步：precheck——先检查再动手

| 项 | 内容 |
|---|---|
| 输入 | 原始材料（md、txt、docx 三种之一），或已有 PPTX；选定的主题；运行方式（完整链路或零配置纯美化） |
| 输出 | 检查结论：环境齐不齐、材料齐不齐、缺什么、能不能往下走 |
| 通过标准 | 1. 材料能读到，不是空文件、不是损坏文件；2. 主题存在且可用；3. 本步需要的工具都已就位，缺的工具已明确列出；4. 材料里的事实来源能找到出处，没有“回头再查”的空位 |
| 常见返工点 | 1. 材料是扫描件或图片型文档，文字抽不出来；2. 主题名字写错，跑到一半才发现；3. 渲染工具没装，跑到验收才发现验不了；4. 素材缺位没标出来，生成阶段才发现某页的图片一直没到位 |

### 3.2 第二步：run——生成或美化

| 项 | 内容 |
|---|---|
| 输入 | 第一步通过的材料与主题 |
| 输出 | 落盘的 PPTX 初稿：每页标题、正文、图片、数据、页码齐全 |
| 通过标准 | 1. 每页内容与材料一一对应，没有材料外多出来的页，也没有材料里有、初稿里没有的页；2. 文字是定稿文字，不是占位文字；3. 数据与材料一致，数字、单位、年份逐项核对过；4. 图片清晰、与内容相关，来源合规 |
| 常见返工点 | 1. 文字还是草稿语气，带“大概”“左右”“差不多”，锁定后才发现要改措辞；2. 数据与材料对不上，数字抄错、年份写错，验收阶段才发现；3. 图片分辨率不够，投影放大后模糊，验收阶段被迫换图；4. 一页塞了两件事，标题盖不住内容，验收阶段被迫拆页 |

### 3.3 第三步：validate——独立验收器重读落盘文件

| 项 | 内容 |
|---|---|
| 输入 | 第二步落盘的 PPTX、原始材料、锁定清单 |
| 输出 | 验收结论：逐项打勾的验收表，通过，或哪一项没过 |
| 通过标准 | 1. 验收器自己打开磁盘上的 PPTX 重读，不是读生成器的日志；2. 事实逐项核对：文字没丢、没多、没改意思，数据与来源一致；3. 版式逐页核对：分区、字号、配色与主题一致；4. 配图来源合规；5. 动画必检门通过（见第七节） |
| 常见返工点 | 1. 只看生成器的日志说“成功”，没重读落盘文件，问题到现场才发现；2. 只检查自己做的页，封面、目录、结尾页漏检；3. 发现问题只修表面，根子在前面的步骤，没回去修，同一问题反复出现；4. 验收表打勾走过场，修完不复检，改完又出新问题 |

### 3.4 第四步：publish——验收通过才定版

| 项 | 内容 |
|---|---|
| 输入 | 第三步验收通过的 PPTX |
| 输出 | 定版的交付稿，版本号固定，可回滚 |
| 通过标准 | 1. 验收表全部通过，没有未解决的项；2. 版本号已记录，旧版留底；3. 定版后内容冻结，见第五节锁定清单 |
| 常见返工点 | 1. 验收没通过就定版，问题被带进交付稿；2. 定版后又悄悄改了一处，没留版本记录，下次不知道哪版是对的 |

### 3.5 第五步：export——导出交付形态

| 项 | 内容 |
|---|---|
| 输入 | 第四步定版的交付稿 |
| 输出 | 按需导出的成品文件 |
| 通过标准 | 1. 导出文件与定版稿内容一致；2. 导出后抽查打开，能正常播放；3. 导出过程不改动定版稿的文字、数据、版式 |
| 常见返工点 | 1. 导出时格式转换丢字、丢图，没抽查就发出去了；2. 导出的文件与定版稿不是同一版，发错版本 |

## 第四节：另外三种跑法

标准五步之外，底座还有三种常用跑法，做法与契约不变，只是入口不同。

| 跑法 | 入口 | 什么时候用 | 注意 |
|---|---|---|---|
| 从原始材料生成 | from-material | 只有 md、txt、docx 材料，还没有 PPTX | 材料要先过 precheck，结构与事实先定下来再生成 |
| 局部修改 | edit | 定版稿只有一两处要改，不想整份重做 | 只改指定的局部，改完要重新跑 validate，改动不得扩散到别的页 |
| 版本回滚 | 回滚 | 新版改坏了，要回到上一个通过验收的版本 | 回滚的目标必须是验收通过的旧版，不能回滚到一个没验过的版本 |

三条红线：

1. **edit 不是绕过验收的后门。** 局部改完必须重新跑 validate，验收通过才能再次定版。
2. **回滚不是删记录。** 回滚后旧版留底，新版的问题记下来，下次不再犯。
3. **任何跑法都不许跳过 precheck 与 validate。** 入口可以换，检查不能省。

## 第五节：主题与依赖

### 5.1 四个主题

| 主题 | 说明 |
|---|---|
| wengao-basic | 默认主题，通用场合先用它 |
| wengao-business | 商务场合 |
| wengao-dark | 深色场合 |
| wengao-minimal | 极简场合 |

主题只定版式与风格，不定内容。换主题不许改文字与数据，换完要重新跑 validate。

### 5.2 依赖清单

| 依赖 | 用来做什么 |
|---|---|
| python-pptx | 读写 PPTX |
| Pillow | 处理图片 |
| lxml | 处理幻灯片内部结构 |
| openpyxl | 处理表格与数据 |
| pypdf | 读 PDF |
| pypdfium2 | 渲染 PDF 做验收比对 |
| python-docx | 读 docx 材料 |
| LibreOffice（本机） | 渲染与验收门禁 |

### 5.3 两种跑法

**跑法一：完整链路。** 本机模型加 LibreOffice 都就位。

- 本机模型指 llama-server、Ollama 或云端端点，用来做由原始材料生成与默认语义场景配图。
- LibreOffice 用来渲染与跑验收门禁。
- 适用：从原始材料生成、需要语义场景配图的场合。
- 诚实状态：这条链路的真实端到端能力目前是开发候选，未验证（见第九节）。

**跑法二：零配置纯美化。** 只装 LibreOffice 就能跑。

- 命令：run --skip-scene-photos，跳过场景配图，只做纯美化。
- 从 2026-11-15 起支持，适用：已有 PPTX，只想统一版式、修版式问题。
- 不需要本机模型，不生成新配图，不编新内容。

### 5.4 没装 LibreOffice 时怎么办

渲染类验收跳过，但必须明示，不许假装验过。具体做法：

1. 在验收表里把渲染类检查项标为“未执行：未装 LibreOffice”，而不是打勾。
2. 告诉用户：没装 LibreOffice，渲染与像素级比对没法做，交付稿的显示效果未经渲染验证。
3. 其他不依赖渲染的检查照常做：文字、数据、结构、配图来源、动画时间线存在性。
4. 装好 LibreOffice 后，补跑一次完整 validate，补过的项才能打勾。

## 第六节：锁定清单

锁定发生在 validate 通过、publish 定版之后。锁定之后，清单分两边：一边是锁定后才允许改的东西，一边是锁定后不许改的东西。

### 6.1 锁定后才允许改的东西

| 允许改 | 说明 |
|---|---|
| 动画效果 | 进入、强调、退出、动作路径四类动画的种类、顺序、延迟、时长（按模块 B 做） |
| 切换效果 | 页与页之间的切换种类与时长 |
| 触发器 | 哪个元素被点击后触发哪个动画 |
| 时间线节奏 | 先快后慢的节奏、错峰的间隔、自动衔接还是点击衔接 |
| 动画素材 | 为动画服务的视频、GIF 素材的替换（只换素材，不换位置与尺寸） |

### 6.2 锁定后不许改的东西

| 不许改 | 说明 |
|---|---|
| 讲稿文字 | 标题、正文、注释的任何一个字 |
| 讲稿顺序 | 页的顺序、每页要点的顺序 |
| 数据 | 数字、单位、年份、来源 |
| 图片内容 | 图片换内容、换一张不同的图 |
| 版式 | 分区、留白、字号、配色、页眉页脚 |
| 页数 | 增加页、删除页、合并页、拆分 |
| 元素位置与尺寸 | 标题、文字框、图片、图表的位置与大小 |

### 6.3 锁定的例外

只有一种情况可以破例：验收或现场发现事实性错误，例如数据写错、名字写错、年份写错。破例的流程是：

1. 停下手头的动画工作。
2. 按返工规则回到对应的步骤去改（数据错回 run 阶段的源头，文字错回材料阶段）。
3. 改完重新跑 validate，版式重新确认，动画受影响的部分重新检查。
4. 重新验收，复检通过才算过关，重新 publish 定版。

除事实性错误之外，任何“想改得更好一点”的念头，锁定后一律不许动手。想改，留到下一版。

## 第七节：动画必检——接进验收门

### 7.1 硬规则

**产出一定是动画 PPT。**

这不是建议，是硬规则。没有动画的交付稿，验收不通过。

### 7.2 验收器必须查什么

动画加完，验收器除查事实不丢字、版式、配图来源合规外，必须查交付的 PPTX 文件里真实存在动画时间线：

| 检查项 | 怎么做 | 通过标准 |
|---|---|---|
| 动画时间线存在 | 验收器打开落盘的 PPTX，检查幻灯片里有没有 p:timing 时间线 | 每页内容页至少有一组动画，全 deck 至少有一种切换 |
| 动画挂在对的元素上 | 检查时间线指向的元素是不是还存在、位置对不对 | 没有指向已删除元素的时间线，没有错位 |
| 动画顺序与讲解一致 | 对照讲稿逐页核对播放顺序 | 先讲的先出现，后讲的后出现 |
| 动画没改动锁定内容 | 对照锁定前的定版稿比对文字与数据 | 标题、正文、数据一个字都没变 |

### 7.3 动画阶段的顺序

1. 稿子（结构、事实、版式）先经 validate 锁定，再进模块 B 加动画。
2. 动画加完，重新跑 validate，验收器重读落盘文件。
3. 动画不得改动已锁定的文字与数据。发现动画阶段想改文字的，按返工规则回对应的步骤，不许就地改。
4. 验收不过，不许说“好了”，不许 publish，不许 export。

### 7.4 返工对照表

| 问题出在哪 | 回到哪一步 | 回去做什么 | 做完还要做什么 |
|---|---|---|---|
| 讲稿逻辑不通、结论不对 | 材料阶段 | 重写相关段落，通读确认 | 重走 precheck 到 export |
| 讲稿有事实错误 | 材料阶段 | 核对来源，修正文字 | 重走 precheck 到 export |
| 每页内容分配不合理 | run 阶段 | 重新切页、调整要点 | 重走 validate 到 export |
| 文字措辞要改 | run 阶段 | 改文字，核对数据 | 重走 validate 到 export |
| 数据错了 | run 阶段 | 核对原始来源，修正数据 | 重走 validate 到 export |
| 图片错了、要换图 | run 阶段 | 换图，确认清晰度与相关性 | 重走 validate 到 export |
| 版式不统一、字号乱了 | 主题与版式 | 重定样板，全稿统一 | 重走 validate 到 export |
| 动画顺序错了 | 模块 B | 重排时间线与错峰 | 重新跑 validate |
| 动画失效、触发器不工作 | 模块 B | 检查元素绑定，重新设置 | 重新跑 validate |
| 验收发现无动画时间线 | 模块 B | 按模块 B 补动画 | 重新跑 validate |
| 验收发现错字、漏字 | run 阶段 | 改文字 | 重走 validate 到 export |
| 验收发现版式问题 | 主题与版式 | 重定版式 | 重走 validate 到 export |

### 7.5 三条红线

1. **不许就地修补。** 动画阶段发现文字错了，不许直接在动画稿上改一个字。回对应的步骤改，改完重走锁定与动画。直接改的后果是：材料、初稿、定版稿三份文件从此对不上，下次再改没人知道哪份是对的。
2. **不许跳步。** 回到 run 阶段改完文字，不许直接跳回模块 B 加动画。必须经过 validate 重新确认，再进动画。跳过的步骤就是下一次返工的起点。
3. **不许带着问题往下走。** 某一步的通过标准有一项没过，就停在那一步。带着问题往下走，问题不会自己消失，只会越攒越多，最后在验收阶段集中爆发。

### 7.6 返工记录

每次返工记一行：日期、问题、回到哪一步、改了什么、复检结果。记录不用长，一行就够。返工记录的作用是：同样的问题第二次出现时，能立刻知道上次是怎么修的、回的是哪一步，不用重新想一遍。

## 第八节：质检做法

### 8.1 质检必须完整播放一遍

从第一页播到最后一页，中间不许跳页，跳过的页等于没检。质检分两遍：第一遍看内容，对照讲稿逐字核对；第二遍看动画，对照模块 B 的验收门逐项核对。

### 8.2 质检清单

- 每页文字与材料逐字核对，没有错字、没有多字少字。
- 每页数据与原始来源核对，没有数字错误。
- 每页版式与主题核对，分区、字号、配色一致。
- 每页动画时间线真实存在，顺序与讲解一致。
- 全 deck 至少有一种切换效果。
- 发现问题先记下来，再按返工规则决定回哪一步。不要边检边改，边检边改容易漏检后面的页。
- 修完必须复检。复检只检修过的页与受牵连的页，复检通过才算过关。
