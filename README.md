## 这是什么

一个做动画 PPT 的 skill：一句话进来，先把稿子稳住，再给每一页配上图、加上动画，最后导出成能当场放出来的成品。底座是路由制工作流（生成 PPTX、美化、改原生 PPTX、建模板四条路线，一次只能选一条），动画能力来自 18 个动画库的融合提炼，插图走程序画图、图库、AI 生图三条路，程序画图首选。

适用的人：要做汇报、讲课、路演、产品介绍的职场人、教师、创业者、学生。
适用场景：从讲稿生成新 PPT、把丑 PPT 变好看、给已有 PPTX 加动画、做品牌模板、做公式与图表页、做 3D 展示页、导出与质检交片。

## 使用方法

1. 先读底座：看有没有 `.agents/PPT动画上下文.md`，有就先读，没有就先建（问用户不超过 5 个关键问题）。
2. 按意图分流：按主 SKILL.md 路由表进对应模块，读 `references/` 里那个模块的全文再干活。先稳稿后动画，稿子不定型不许动动画。
3. 先过硬规则再输出：输出必须是可执行清单（做什么、什么时候做、怎么验收），并给下一步。交付前按模块 E 的质检清单逐项核对，验收不过不许说“好了”。

## 动画招式速查（按页型选招）

| 页型 | 推荐招式 | 出处 |
|---|---|---|
| 封面 | 粒子背景（星空、飘雪、烟花）循环播放；3D 产品旋转开场；弹簧入场 | Proton、Babylon.js、Three.js、Motion |
| 目录 | 列表逐个错峰入场；分层图解点一点出一层 | Anime.js、Motion、Konva.js |
| 要点 | 时间线加错峰，逐个出现；讲解视频逐句展开；GIF 轻动效 | Anime.js、Remotion、Motion Canvas、gifenc |
| 数据 | 数字平滑滚动到新值；图表生长动画；讲解视频带字幕 | Ola、Remotion、Motion Canvas |
| 公式 | 公式一步步写出来，图形随公式变化 | Manim、Motion Canvas、Two.js |
| 图表 | 矢量图解动画；分步演示先移过去再放大 | Two.js、Shifty、TweenJS |
| 结尾 | 粒子背景；3D 环绕收尾；讲解视频收束 | Proton、Blender、Remotion |

选招原则：正文页每页 1–2 组动画就够，不要堆招式；封面与结尾可以活泼一点，正文页保持克制；同一个招式全 deck 只用一次思路，不要每页换一种。

## 交付前自查清单

- [ ] 稿子定了吗？讲稿、页数、结构都定了吗？
- [ ] 每页内容页至少 1 组动画，全 deck 至少 1 种切换？
- [ ] 动画默认自动连播，翻到一页不用点就自己播，全页点击触发的页清零了吗？
- [ ] 动画核对命令跑过了吗？输出 PASS 了吗？FAIL 的页修完复检了吗？
- [ ] 对比度、空白占位、装饰盖字、竖条内收、甘特条带字，五项都查了吗？
- [ ] 时间线先快后慢可调，改一个数字就能改节奏？
- [ ] 触发器点一点才出现，不点不出现？
- [ ] 视频、GIF 素材在 PowerPoint 或 WPS 放映模式下能正常播放？
- [ ] 在目标放映尺寸下检查过一遍，换电脑、换投影比例不乱版？
- [ ] 交付说明写了吗？文件名、版本号、动画清单、插图清单、播放要求、素材清单、已知问题、下一步都齐了吗？
- [ ] 有一项没过，就回去修，修完重新自查，不要跳过。

## 常见问法

- “帮我做个 PPT”：先问讲什么、给谁讲、多少页，问完先进模块 A 定稿。
- “这个 PPT 太丑了”：先备份原文件，再进模块 C 重排版式。
- “给这个 PPT 加点动画”：先进模块 B，定好动画基调再动手。
- “做个模板以后都能用”：进模块 C 只做模板，不做成品。
- “导出来发我”：进模块 E，先质检再交付。

## 模块分工与阅读顺序

- **先读模块 A：** 不管做什么 PPT，先把稿子定下来。讲稿、页数、结构、风格没定，后面全是返工。
- **再读模块 C：** 稿子定了，先排版式。版式是 PPT 的骨架，骨架歪了，动画再好看也救不回来。
- **然后读模块 B：** 版式定了，再加动画。动画是给内容服务的，不是给页面贴花的。
- **按需读模块 D：** 遇到公式、图表、3D 展示页才读，不用每份 PPT 都读。
- **最后读模块 E：** 交片前必读。导出、质检、交付说明都在这里，清单不过不许说“好了”。

一次只进一个模块；问题跨两个模块时，先做主模块，做完再进下一个。不要五个模块同时开工。

## 硬规则速览

1. 产出一定是动画 PPT：每页内容页至少 1 组动画、全 deck 至少 1 种切换、时间线先快后慢可调，动画默认自动连播，验收不过不许说“好了”。
2. 先稳稿后动画，稿子不定型不许动动画。
3. 诚实：python-pptx 不支持直接加动画，靠注入 p:timing 时间线，必须在 PowerPoint、WPS 里实际播放检查。
4. 不确定的一律写“需核实”。
5. 不复制原文，全部中文重写。
6. Plan→Do·Check·Act，串行执行，阻塞门等用户确认。
7. 输出格式：先给结论，再给可执行清单，最后给下一步。

完整硬规则见 SKILL.md。

## 适用与不适用

- 适用：汇报、讲课、路演、产品介绍、答辩、培训等需要“讲清楚＋讲得动”的场合。
- 适用：从零做新 PPT、美化旧 PPT、给旧 PPT 加动画、做品牌模板。
- 不适用：纯文字文档、纯数据表格、不需要放映的资料——这些不用动画，直接交文档更合适。
- 不适用：讲稿还没影、连讲什么都没想好——先想清楚讲什么，再回来用本包。
